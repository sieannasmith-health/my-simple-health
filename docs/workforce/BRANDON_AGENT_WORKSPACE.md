# Brandon — Co-Founder Agent Workspace

## Purpose

This file defines the shared GitHub-backed operating context for Brandon's MSH co-founder work. It is designed so Brandon can use his own ChatGPT account, connected to the same MSH GitHub repository, without receiving Siea's private ChatGPT conversation history.

GitHub is the durable shared company context and work/evidence layer. ChatGPT is the conversational surface. HelloSimple will later become the employee-facing orchestration surface.

## Role posture

Brandon is a public-facing MSH co-founder/operator with a working focus on B2B, commercial strategy, growth, partnerships, communications, external representation, project leadership, and initiatives that fit the approved MSH company and product scope.

This is not a narrow task-runner role. Brandon should be able to ideate, explore, challenge assumptions, develop strategies, organize initiatives, prepare external-facing work, and lead scoped projects with agent support.

His current title/role language is provisional until Harper completes role-and-strengths discovery with Brandon.

## Strengths discovery requirement

Harper owns the initial evidence-based capability profile.

Before finalizing Brandon's role model, Harper should:

1. Ask Brandon for his resume, LinkedIn profile, portfolio, or equivalent work-history evidence.
2. Review his background in digital marketing, mass communication/media studies, project management, leadership, public-facing communication, and related experience.
3. Interview Brandon about what he wants to bring to MSH, what work energizes him, where he believes he can create value, and what he wants to learn or develop.
4. Distinguish demonstrated experience from interests, aspirations, and areas still being tested.
5. Return a proposed capability profile, role scope, development areas, and initial workstreams to Nomy for Product/company-boundary acceptance.

Do not force Brandon into a generic growth persona or infer expertise solely from a title.

## Operating model

Brandon should be able to begin with an idea, question, opportunity, relationship, or external signal. The agent team should help turn that into a bounded piece of work.

Preferred flow:

**Idea / opportunity -> clarify objective -> gather evidence -> develop options -> test assumptions -> identify risks/dependencies -> recommend next step -> obtain required decision/approval -> execute authorized work -> preserve evidence/results in GitHub.**

Early-stage ideation should remain exploratory. Agents should not treat every idea as a committed roadmap item.

## Shared-context rule

When working from Brandon's ChatGPT account, use this repository as the shared source of truth for company/product work.

Read, at minimum, when relevant:

- `AGENTS.md`
- `docs/SIMPLE_PRODUCT_CONTRACT.md`
- this file
- the active GitHub issue/PR/discussion for the work
- relevant product, workforce, architecture, compliance, evidence, or strategy documents referenced by the task

Do not claim access to Siea's private ChatGPT conversations. Do not infer private founder-only context that is not represented in approved shared company artifacts.

## What belongs in GitHub

Use GitHub to preserve consequential shared work:

- ideas that become active investigations
- B2B hypotheses
- partnership concepts
- positioning or campaign proposals
- stakeholder research
- commercial assumptions
- decisions and rationale
- assigned work
- agent handoffs
- artifacts and evidence
- implementation requests
- QA/review results

Private brainstorming that has not become company work does not need to be committed to GitHub.

## Authority boundaries

Brandon may ideate broadly within MSH's mission and company context. He may lead scoped B2B, commercial, communication, partnership, growth, and project initiatives once they are accepted into the active company workstream.

The following require the appropriate approval/review before commitment or execution:

- material changes to MSH product scope or roadmap
- external medical or health claims
- changes to privacy, health-data use, consent, or sharing
- binding contracts or financial commitments
- security-sensitive access or permissions
- public statements representing unapproved company positions
- regulated or compliance-sensitive activity
- commitments that materially change company strategy or obligations

XP, gamification, or progression status never grants authority.
